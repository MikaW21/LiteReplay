# 架构及实现边界

## API 选择

Windows Graphics Capture 适合后续独立窗口选择；需要额外的 WinRT 捕获项、帧池、尺寸改变和授权/选择器处理。本首版选择 Desktop Duplication，以缩小未经实机验证的接口范围。它只捕获显示器，不能自动等价于游戏捕获。

直接使用 NVENC SDK 可以减少中间层，但仍需管理编码会话、D3D11 输入资源、异步结果、各编码参数和容器。首版用 FFmpeg NVENC 封装这些工作；由 nvcodec 依赖提供头文件，运行时使用驱动中的 NVENC API。不需要 CUDA Toolkit 或 NVIDIA App。

WASAPI Loopback 直接读取默认播放端点，避免虚拟声卡。两个 WASAPI 线程可分别读取系统和麦克风；独立的 48 kHz 双声道、两秒 PCM 时间轴按 QPC 定位。AAC 是少量 CPU 音频编码，不是 CPU 视频编码。

## 所有权和线程

| 线程 | 资源与工作 |
|---|---|
| UI | 消息循环、托盘、热键、设置、每秒进程性能计数 |
| 捕获/编码 | D3D11 设备、Duplication、GPU Frame Pool、NVENC、AAC；串行使用立即上下文 |
| 系统音频 | COM MTA、默认播放 WASAPI、重采样、PCM 时间轴 |
| 麦克风 | 按需存在；默认输入 WASAPI、独立重采样/时间轴 |
| 保存 | 单个快照、封装器、文件；与 D3D11/编码器没有共享可变状态 |

FFmpeg 编码输出转为不可变共享字节数组。Session 含配置、编码参数副本和 ring；Session 发布前完成编码器初始化。保存任务持有自己的 Session 引用，捕获恢复可创建新 Session，不会把新的 extradata 用在旧快照上。

GPU 帧池固定 16 个 NV12 surface，输出 view 缓存复用。桌面 BGRA 纹理是一张 GPU texture；CopyResource 和 VideoProcessorBlt 不进行 CPU readback。NVENC 输出的压缩数据才进入 RAM。

## GOP 缓存规则

- 没有第一个视频关键帧时，不收依赖帧/音频。
- 最新视频时间决定时间窗口；保留窗口起点之前最近一个关键帧，长度可比设定多约一个 GOP。
- 字节或包数量达到上限：整组淘汰，若连一组也装不下则丢弃并等下一个关键帧。
- 迟到的 AAC 包按 PTS 归入对应 GOP；早于保留起点的包直接丢弃。
- 导出快照在短锁内复制元数据/共享指针，排序在锁外。payload 不随 snapshot 复制。
- 快照和活跃缓存最多各保留一份容量；单保存策略防止多份快照无界增长。
- 内存上限缩短实际时长时不伪造补满 N 秒。

## 时间戳

会话建立一个 QPC epoch。WASAPI 的 GetBuffer QPC 值已经是 100ns 单位，不把它误当成原始 QPC tick。视频采样时钟同样换算至 100ns。

视频 PTS 为相对时钟换算后的帧编号；遗漏的帧编号不加速视频。音频样本按 QPC 放到 48000Hz 栅格，扣除 resampler 延迟；独立设备时钟以每个包时间戳不断重新锚定，防止简单“从零累加音频帧数”的持续漂移。没有实现高阶异步时钟校正，仍需长时间同步测试。

混音线程延迟 100ms 消费 PCM，允许 WASAPI 先送达；缺口补零；PCM 超出两秒则放弃过期数据并跳至当前时间。独立音轨共用相同的音频样本编号。

保存减去统一的视频关键帧起点，而不是对每条流各减自己的首包时间。末尾裁到所有流已完成的共同区间，避免音频流水线延迟形成长静音尾。AAC 切片边界可能有约一个编码帧（1024/48000 秒）的误差；无法用纯时间戳检查证明听感同步。

## 恢复

DXGI access lost、D3D/NVENC 错误会退出当前对象作用域；RAII 释放帧、设备、编码器和音频线程，按退避延迟重建。未保存旧缓存丢失，但保存线程自己的引用仍有效。设备切换由 WASAPI 线程独立重连。

停止请求是原子状态；UI 不等待捕获线程退出，下一轮计时器显示 Stopped。最终退出 join 所有自有线程；未提供卡死驱动强制线程终止，因为强杀线程会破坏资源状态。因此仍须做驱动/硬件异常测试，不能据代码宣称“绝不会卡死”。
