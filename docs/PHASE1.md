# LiteReplay 2.0 — Phase 1 开发预览

日期：2026-11-09（北京时间）。这是统一框架的第一份开发构建，不是 2.0 正式版。Phase 1 的 Windows 实机回归仍待完成，因此本次不进入 Phase 2。

## 已实现的改动

- 一个 LiteReplay.exe 主入口、七项左侧导航、可缩放原生窗口、内容区滚动。没有 Electron/WebView，也不启动独立剪辑 GUI。
- 首页展示真实 CPU/GPU/RAM 与本进程占用。缺失采样显示 N/A，不把录制帧率当游戏 FPS。
- 即时回放页面保留原有参数、全局保存热键、托盘、保存提示音与真实录制控制。
- 音频控制台作为主窗口子页面运行；离开该页、最小化或隐藏主窗口时关闭其计时器并释放音频会话；返回时重新枚举。
- 性能详情移入主程序页面；旧版 HUD 仍可通过设置窗口或 Ctrl+Shift+F9 使用。尚不是任务书中的 A–E 系统。
- 外置 languages/zh-CN.lang 和 en-US.lang。主导航、首页、回放设置标签、主要按钮、托盘菜单和统一设置支持即时切换，保留未应用的输入值，不重启录制。
- 平衡为默认模式，极低资源/平衡/性能分别使用 2000/1000/250 ms 的监控和活动页面刷新间隔。策略另定义后续预览与导出预算，当前未接入这些尚未实现的模块。
- 没有首页/监控页/HUD 订阅时销毁 Performance 对象、等待其线程停止并关闭 PDH 查询。隐藏主窗口且未开启 HUD 时不保留主界面刷新计时器；静态设置/占位页面也不持续刷新。
- 新设置位于 `%LOCALAPPDATA%\LiteReplay\2.0\settings.ini`，所有已接入模块共享该文件。首次迁移复制旧设置并留 `settings-1.4-backup.ini`；不写回 1.4 INI，不默认注册新版本开机启动。已有系统启动项不在启动迁移时自动改动。
- 6 个录制核心文件与 1.4 完全一致，校验见 validation/engine-preservation.json。没有改变视频捕获、硬件编码、音频时钟、循环缓存或封装算法。

## 仍未完成

媒体库和剪辑页明确显示后续阶段说明，没有虚假的导入、时间轴或导出按钮。QSV/AMF/CPU 回放、A–E HUD、传感器/游戏 FPS、后台负载自适应、预览/导出调度均未实现。

中英文切换目前覆盖新主界面和回放主要操作；旧音频/HUD配置面板、部分异常消息及原始诊断仍为中文。完整英文化未验收。音频页面仍保留旧控件样式，尚未统一深色细节。

窗口采用系统 DPI 感知与滚动布局，尚未进行逐显示器 DPI/低分辨率视觉验收。不能据交叉编译成功承诺所有控件无裁切。

现有保存完成接口仍沿用 1.4 回调，类型化媒体事件在 Phase 2 接入时实施。设置沿用共享 INI API，已有录制设置仍逐键写入，不宣称整体事务提交。三个模式只调整当前已接入的刷新/订阅行为；不会修改录制分辨率、帧率、码率或环容量，不会因切模式丢弃缓存。

## 构建与测试

本次使用 MinGW GCC 13 POSIX 交叉编译 Windows x64 主程序和诊断程序；复用基线 FFmpeg 7.1.1 DLL。Windows 链接新增 ksuser 以解析 WASAPI 格式 GUID。运行时不需要用户安装该编译器。主程序静态链接 GCC/C++/线程运行时，FFmpeg 仍为可替换的共享 DLL；许可见随包 notices。

可移植验证：4 个 C++ 测试程序构建及运行、7 项 Python 用例，共 9 个外部命令全部通过。新测试覆盖默认/无效模式、监控订阅、语言解析失败保持旧数据、词条重复拒绝、中英键集合一致。原缓存、音频时间轴、配置和 EQ 逻辑测试继续通过。

没有运行 Windows GUI、真实 NVENC/WASAPI、APO 或游戏测试；没有任何实测 CPU/内存/GPU/帧率损失数据。本次 EXE 属于已交叉编译、尚待 Windows 验证的开发版本。

## Windows 手动验收（必须记录结果）

1. 从托盘完全退出 1.4，解压到新目录，保留整个 bin/windows-x64 目录内容；运行 LiteReplay.exe。不要只复制 EXE。单实例锁与旧版共用，防止同时录制冲突。
2. 检查首页和七项导航；缩放至 800×600，验证内容能通过滚动访问；检查中文路径、中文和英文切换。缺少语言目录应给出明确启动错误。
3. 首次启动检查旧 INI 字节未变、新 INI 与备份存在；默认平衡、未强制开机启动；退出重开确认语言/模式持久化。保留原开机启动项，只有用户改变开机启动勾选时才修改注册表。
4. 使用已在 1.4 成功的 NVIDIA SDR 屏幕配置，开启回放。分别切七页、切语言、切三模式、缩放/最小化/托盘还原，再按保存热键。检查文件真实可播放、系统音与麦克风、提示音，以及缓存未因模式切换重建。
5. 在任务管理器或诊断工具检查：退出音频页后不再枚举会话；关闭 HUD 且离开首页/监控页后采样线程与 PDH 查询释放。打开 HUD 后重新获得数据，不显示旧值冒充实时。
6. 检查音频页返回、设备消失、音量/静音实际生效。EQ 仍需已安装并绑定设备的 Equalizer APO；写配置成功不代表已验证音效。不要在本测试中覆盖不相关 EQ 配置。
7. 托盘隐藏/显示、Ctrl+Shift+F9、退出、保存中退出、磁盘满等场景记录日志和错误。验证没有残留进程。
8. 双击 TestReplay.cmd 可执行约五秒真实捕获诊断；它会创建测试录像与日志，不是性能测试。试听并检查文件。把失败的 probe-log.txt / 新版本 LiteReplay.log 保留以定位问题。

上述 Windows 检查没有通过前，Phase 1 状态保持“开发构建，待实机验收”，不得进入 Phase 2 的完成宣告。
