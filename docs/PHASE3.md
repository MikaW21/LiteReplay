# Phase 3a 基础视频剪辑

软件由 Yuzi_Lj 制作 / Software by Yuzi_Lj。2026-11-09。

这是 Phase 3 的首个可操作开发版本，不代表 P3 全部完成。Phase 1/2 的 Windows 全面回归仍待完成；用户此前仅反馈截图功能可用。

## 复用与集成

审查并复用原 LiteCut 0.1 的工程格式、参数构造、顺序片段导出、MFPlay 预览和受控子进程代码。编辑界面编译进 LiteReplay.exe，嵌入左侧“视频剪辑”页，不启动 LiteCut.exe。FFmpeg/FFprobe 只作为主程序控制的媒体处理子进程运行。它们与回放 DLL 分开放置，互不替代。录制引擎源码保持 Phase2c 原样。

## 使用流程

1. 先停止即时回放。进入“视频剪辑”，点“导入视频”；也可以在媒体库选择录像，点“进入视频剪辑”。导入后台读取视频时长和是否有音轨，单个探测最长 30 秒，工程最多 256 段。
2. 左侧选择片段，点击“播放/暂停”。预览一次只播放选中片段。Windows 缺少解码器时可报错；不伪造画面。
3. 拖动源视频进度条或时间轴定位。输入入点、出点（秒），或点“设为入点/出点”，再点“应用裁剪”。未应用的输入不进入工程和导出。
4. “此处分割”在播放头处拆分已应用的片段；两段至少各 0.04 秒。上移/下移改变拼接顺序，复制/移除只修改工程，不删除原视频。
5. 音量 0–200%，0 静音。只处理第一条源音轨；无声源在常规导出补静音。预览音量最多 100%，超过 100% 的增益只在导出应用且可能削波。
6. 时间轴显示视频片段和对应音频状态条（不是独立可编辑多音轨），黄色线为播放头。按放大/缩小调整倍率，滚轮横向移动视图。拖动定位；排序使用上移/下移按钮，不支持拖动换序。
7. “保存工程”保存 .lcut；“打开工程”恢复。路径和媒体引用保持原格式兼容。Ctrl+I/O/S 导入/打开/保存。撤销/重做最多 64 个快照、合计 16 MiB；编辑输入框内 Ctrl+Z 保留原生文本撤销。
8. 已应用的修改约 800ms 后自动保存至 `%LOCALAPPDATA%\LiteReplay\2.0\editor-autosave.lcut`。“恢复自动保存”读取它；工程不包含源视频。保留原路径，缺失源需重新导入。自动保存是最近一个工程快照，不是多工程历史备份。

## 两种导出

常规导出：按片段顺序重编码、缩放并补黑边，最终拼接为 MP4。720p/1080p/1440p，24/30/60/75 FPS。提供 H.264 NVENC、HEVC NVENC，以及明确标注的 CPU MPEG-4 Part 2 兼容选项。CPU 选项不是 H.264，使用固定 q=3，码率输入不生效。NVENC 仅加速编码，解码与滤镜仍会使用 CPU。

快速裁剪导出：仅导出当前选中片段，stream copy 不重新编码。必须保持音量 100%；不应用输出分辨率/FPS/码率设置。起点受关键帧影响，可能包含额外画面，不能保证精确到任意帧。MP4 不支持的编码组合会失败，不会暗中重编码或覆盖目标。

导出只允许新文件名。原视频不改动；输出先写本次临时目录，探测包含视频轨后以不覆盖方式提交。常规流程还检查音轨。验证不是完整逐帧质量验收。导出成功自动加入媒体库。取消会终止作业并清理本次目录；强制杀死进程可能留下 `.LiteReplay-edit-*` / `.LiteReplay-copy-*`，确认没有任务后可清理。所有日志在统一设置目录 `editor-export.log`。

## 资源与限制

编辑器首次进入时才创建。离开剪辑页、最小化或关闭到托盘会 Shutdown 预览并释放播放器。没有预览/导出/导入任务时不持续刷新。导出仍可在切页后完成。

回放优先策略采用明确互斥：回放运行时不允许剪辑预览与导出；从主程序开启回放会取消并收尾当前编辑任务。不会无条件抢占回放编码器，但这还不是高效的录制/导出并行调度。取消收尾可能短暂等待。

导出默认 IDLE 优先级，性能模式 BELOW_NORMAL。模式给下一进程应用优先级，编码线程提示低资源 1 / 平衡 2 / 性能 4，滤镜线程 1；这些不是系统 CPU 硬性占用上限。当前片段已启动的线程设置不追溯变更。模式切换不重启录制或损坏工程。窗口内固定紧凑布局配合统一页的水平/垂直滚动，低分辨率要滚动查看。

随附工具暂不包含 AV1 解码器，AV1 可在兼容容器下尝试 stream copy，但不能据此承诺 AV1 重编码剪辑。HDR 无色调映射。重编码导出未接入 AMF/QSV/MF；这不撤销回放已有 AMD/MF 功能。
